# 020 - 시트 동기화 리팩터링 (한도 대응 · 손상 버그 수정 · 알림)

## 왜

시트 API 한도는 사용자당 읽기·쓰기 각 **60/분**(공식), 배치 요청은 1건, 틱은 20초(분당 3회).
갱신 경로가 항목마다 시트 전체를 읽어 버스트 시 429 위험. Koyeb 이행 전 정리 (사용자 요청 2026-09-07).

## 문제 (코드 읽기에서 발견)

1. `update_bookmark/subscription/user`: 항목마다 `get_all_records()` 읽기 1 + `update` 쓰기 1.
   갱신 20건 버스트면 분당 120+ → 429.
2. **데이터 손상**: 키를 못 찾으면 `row_number` 가 초기값 2인 채 `update` → 첫 데이터 행을 덮어씀.
3. `initial_queue` 가 값 동등성으로 큐를 정리 → 업로드 중(await 지점) append 된 동일값이 걸러져 유실.
4. 429 에 백오프 없음: 20초마다 재시도 + 매번 관리자 알림. shutdown 의 마지막 flush 는 백오프를
   넣으면 건너뛰어질 수 있음.
5. self-ping 실패는 로그만. URL 이 틀리면 1시간 뒤 잠들어도 아무도 모름.

## 해결

- 갱신 3테이블: 틱당 `values_batch_get`(키 컬럼만) **읽기 1** + `values_batch_update` **쓰기 1**.
  append 를 먼저 올린 뒤 읽어 같은 틱에 추가된 행도 찾는다. 못 찾으면 **어떤 행도 쓰지 않고**
  버린 뒤 알린다.
- 큐 정리를 인덱스 슬라이스(`_drain` / `_commit`)로. 동일값도 안전.
- 429 → 틱 단위 백오프 1·2·4분, 최대 5분 (`SheetQuotaExceeded`). 3회 지속 시만 알림.
  `upload_queue(force=True)` 로 shutdown 은 백오프를 무시하고 한 번 시도.
- writing_participation: 시트와 user_id 합집합(로컬 우선) 후 `replace_table`(resize 1 + update 1). 빈 창 없음.
- 틱 요청 예산 20, 초과분 이월(시작 시 1회 알림). 정상 최악 11/틱 ≈ 33/분 (< 60).
- `keepalive_job`: self-ping 3회 연속 실패 시 1회 알림, 성공하면 리셋.
- 알림 정책은 순수 함수 `flush_alerts` 로 분리해 테스트. 클라이언트 `update_*` 3개 제거(호출처 store 뿐).

TDD 실패·성공·엣지: 신규 56종 (store 42 · client 10 · keepalive 4). 전체 **333 passed**.

## 기존 동작과 달라진 점 (모두 의도)

못 찾은 갱신은 버리고 알림(전엔 2행 손상) · 429 는 백오프(전엔 20초 재시도) · shutdown flush 강제.

## 사용자 검증 방법

1. **정상**: 북마크 메모 수정 → 20초 안에 시트 `bookmark` 탭의 **그 행만** 바뀜. 로그 `updated_bookmarks`.
2. **엣지·알림**: 시트에서 어떤 북마크 행을 지운 뒤 그 북마크를 수정 → 관리자 채널에
   "못 찾아 건너뛴 항목 1건" 알림이 오고, 시트 **2행은 그대로**.
3. **self-ping 알림**: `KOYEB_URL` 을 일부러 틀리게 두면 15분 뒤 알림 1회, 그 뒤 반복 없음.
4. 429 는 재현이 어렵다. 단위 테스트(1·2·4·5·5분 상한, force 우회)로 갈음.

## 교차검증 반영 (2026-09-08, 서브에이전트 3종 리뷰)

리뷰가 실제 결함으로 확인한 것을 같은 관심사로 묶어 고쳤다. gspread 소스로 직접 재확인함.

- **심각** `replace_table` 이 캐시 `row_count` 에 의존. gspread `append_rows` 는 grid 와 무관하게
  캐시만 +N 한다(worksheet.py:1864) → 자동 생성 탭(캐시 1001 vs 실제 1000)에서 `values.update` 400,
  첫 신청부터 WP 동기화가 매 틱 실패. → `resize(len)` + `update`(쓰기 2회, 캐시 무관). 헤더도 `update` 로.
- **중간** 틱 도중(await) 들어온 "생성 + 즉시 취소" 가 갱신만 이번 틱에 처리돼 시트에서 못 찾고 버려짐
  → 어떤 await 전에 **모든 큐를 스냅샷**. 핸들러는 생성→갱신 순으로 동기 enqueue 하므로 안전.
- **중간** 시트에 같은 키 행이 둘(재북마크)이면 첫 행만 갱신 → 일치하는 모든 행에 같은 값.
- **중간** Koyeb 배포 겹침 구간에 옛 인스턴스가 늦게 올린 WP 행을 통째 교체가 지움
  → user_id 합집합(로컬 우선) 뒤 교체, 로컬에도 되씀. WP 비용 1 → 3.
- 낮음: `zip(strict)` · shutdown flush 예외 격리 · 성공 시 `_backoff_until` 리셋 · 백오프 틱은 이월
  상태 미변경 · WP 파일 IO 를 루프에서(찢긴 읽기 방지) · 빈 탭 pull 시 헤더 1행 · 08:00 잡
  `misfire_grace_time=3600`(0.1 vCPU 에서 1초 지연으로 건너뛰던 것).
- 429 알림은 3회부터 백오프 주기(≈5분)마다 반복한다. 지속 장애는 계속 알리되 20초 스팸은 막는 의도.
