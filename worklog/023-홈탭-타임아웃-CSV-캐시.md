# 023 - 0.1 vCPU 에서 홈 탭 타임아웃 · 포인트 내역 trigger 만료

## 왜

Koyeb 이전(09-11) 뒤 22:19 홈 탭 `views.publish` TimeoutError 2건(한도 8초), 22:32 [포인트 획득 내역 보기] `expired_trigger_id` 2건(한도 3초).

## 문제

- 요청마다 users(1.1MB)·contents(4.2MB)·point_histories(4.1MB)를 이벤트 루프에서 통째로 파싱. 로컬 약 0.1초인 경로가 운영에선 약 3.6초 걸렸다. 루프가 멈춘 흔적: `upload_queue ... missed by 0:00:01.1`. (배포 뒤 실측해 보니 운영 파싱은 로컬의 2~3배 수준이다. 3.6초는 CPU 속도보다 루프에 쌓인 동시 작업 탓.)
- 봇 DM(메시지 탭)을 열어도 홈을 다시 그림. `get_user_point` 는 미들웨어가 읽은 유저를 또 읽음. `/v1/contents` 도 요청마다 5MB 파싱.

## 해결

- 메시지 탭이면 미들웨어·핸들러 모두 건너뜀. 미들웨어만 바꾸면 `user=None` 분기가 등록 멤버 홈을 미등록 안내로 덮어써서 둘을 같이 바꾸고 결합 테스트로 고정.
- `get_user_point(user=...)`: 주입된 유저를 그대로 씀 (호출처 3곳).
- `app/table_cache.py`: (inode·크기·수정 시각)이 바뀔 때만 다시 파싱. 2초 안에 바뀐 파일·읽는 도중 바뀐 결과는 캐시 안 함. 앱이 추가한 한 줄은 크기 검증 뒤 캐시에 바로 반영(디스크처럼 universal newline). 앱 안 재작성(pandas·`Store.write`)은 `invalidate`. 행은 tuple, 모델은 매번 새로.
- 부팅 워밍업(09-12): 복원 뒤·소켓 연결 전에 표 3개와 인덱스를 읽어 둠. 방금 복원된 파일은 2초 규칙에 걸려 최대 2초 기다림. 실패해도 부팅은 계속(로그·관리자 알림).
- 서브에이전트 리뷰 반영(09-12, 2회): 따옴표 안에서 잘린 파일엔 이어 붙이지 않음(줄마다 따옴표를 세어 홀수 판정. 파일 전체를 읽어 세면 파싱 중 임시 메모리가 표마다 +20MB라 스트리밍 유지) · `Store.write` 무효화 · 2초 규칙·끼어든 쓰기·파싱 메모리를 고정하는 테스트(규칙을 끄면 실패함을 돌연변이로 확인).
- 범위(사용자 결정): SlackRepository 표 3개 · `/v1/contents`(polars 표 `clone`) · 워밍업. 에러 핸들러 버그·"모달 먼저 열기"는 TODO.
- TDD 신규 74 (캐시 단위 31 · 저장소 결합 28, 옛 구현 동등성 20 포함 · 탭 6 · 포인트 6 · 라우터 3). 전체 420 passed.

## 사용자 검증 방법

1. 배포 전: Koyeb 메모리 그래프에 40MB 이상 여유가 있는지.
2. 배포 로그: `표 캐시 워밍업 완료: N초` 가 찍히고 배포가 healthy 로 넘어가는지. N 이 운영 파싱 실측.
3. 정상: 홈 탭 → 바로 뜸. [포인트 획득 내역 보기] 여러 번 → 모달이 뜨고 `expired_trigger_id`·`TimeoutError` 없음.
4. 엣지: 봇 DM(메시지 탭)만 열기 → 로그엔 `홈 탭 열림`, 홈 화면은 그대로. 포인트를 받은 직후 홈 탭 → 새 총점.
5. 관찰 불가: 같은 틈의 같은 크기 재작성·잘린 파일은 재현이 어려워 테스트(`_key_of` 고정·잘린 파일 픽스처)로 갈음.
