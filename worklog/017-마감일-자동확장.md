# 017 - 마감일(DUE_DATES) 자동 확장

## 왜 (배경)

글또 회차 마감일은 `app/constants.py` 의 `DUE_DATES` 라는 **손으로 관리하는 날짜 리스트**였다.
2주마다 회차가 하나씩 늘어나는데, 그때마다 사람이 직접 `datetime.date(...)` 한 줄을
추가해 줘야 했다. 깜빡하면 마지막 마감일이 지난 순간부터 봇이

- `get_due_date()` → `"지금은 글또 글 제출 기간이 아니에요."`
- `Content.get_round()` → `"글또 활동 기간이 아니에요."`

라며 **활동 기간이 끝난 것처럼** 동작했다. (실제로 45회차=2026-07-05 가 지나
있었다.)

## 어떤 문제

1. 마감일을 사람이 계속 추가해야 하는 유지보수 부담.
2. 추가를 놓치면 시즌이 끝난 것처럼 오작동.
3. 그렇다고 "시작일부터 2주 간격 수식"으로 전부 대체할 수는 없다 —
   **4→5회차 사이가 28일(비상계엄 2주 연장)** 이라는 역사적 예외가 있어서,
   과거 콘텐츠의 회차 계산이 틀어진다.

## 어떻게 해결

역사 구간은 그대로 두고, **마지막 마감일 이후만 2주 간격으로 자동 생성**하도록 했다.

- `app/constants.py`
  - `DUE_DATES` → `BASE_DUE_DATES` 로 이름 변경 (역사적 앵커 리스트, 그대로 보존).
  - `DUE_DATE_INTERVAL = timedelta(days=14)` 추가.
  - `get_due_dates(reference_date)` 순수 함수 추가 — 마지막 마감일이 기준일보다
    이르면 기준일 이상이 될 때까지 14일씩 이어붙여 반환. (기준일이 과거/앵커 범위
    안이면 확장 없이 그대로 반환. `BASE_DUE_DATES` 원본은 건드리지 않음.)
- `app/models.py`
  - 정적 리스트를 참조하던 5개 지점(`_is_prev_pass`, `get_due_date`, `is_submit`,
    `get_submit_status`, `Content.get_round`)이 이제 `get_due_dates(현재날짜 또는
    콘텐츠날짜)` 를 호출한다.

## 결과 / ⚠️ 동작 변화

이제 마감일을 손으로 추가할 필요가 없고, 마지막 마감일이 지나도 다음 회차가
자동으로 생긴다.

**의도된 정책 변화(사용자 요청 2026-07-08 — "2주 간격으로 무한히"):**
시즌이 사실상 끝나지 않는다. 위의 두 예외 메시지("기간이 아니에요")는 앞으로
정상 상황에서는 더 이상 발생하지 않는다(0회차 시작일 이전 날짜 같은 비정상
입력에서만 남아있는 안전망).

## 사용자 검증 방법

1. **정상 확인** — 슬랙에서 글 제출/제출 현황 조회 시 현재 회차 번호와 마감일이
   오늘 기준으로 자연스럽게 이어지는지 본다. (예: 2026-07-08 이면 46회차, 마감일
   2026-07-19 로 잡혀야 함.)
2. **강제 재현(엣지)** — 로컬에서 시스템/`tz_now` 를 아주 먼 미래(예: 2027년)로
   두고 제출 현황을 조회 → 예외 없이 회차가 계속 이어지는지 확인.
3. **역사 보존 확인** — 4회차(2024-11-24)~5회차(2024-12-22) 사이 28일 간격이
   유지되어, 그 사이에 제출된 과거 콘텐츠 회차가 예전과 동일하게 계산되는지 확인.

## 곁다리: pre-commit mypy 에서 테스트 제외 (2026-07-08)

이 변경으로 두 테스트 파일이 pre-commit 변경 대상에 들어오면서, **기존부터**
있던 대량의 mypy `arg-type` 오류(HEAD 기준 17개 파일 113개)가 드러났다.
테스트 픽스처는 느슨한 `dict[str, Any]` body 를 슬랙 `TypedDict` 핸들러에
넘기는 구조라 타입체크 실익이 낮다.

- **결정(사용자 2026-07-08):** pre-commit `mypy` 훅에 `exclude: ^test/` 추가.
  앱 코드는 계속 타입체크하고, 테스트는 제외한다. (DUE_DATES 작업과 무관한
  선재 부채였고, 저장소가 사실상 테스트를 타입체크하지 않던 실태와도 일치.)
- 이 커밋에서 드러난 `UserPoint` 미사용 import(F401)는 실제 정리했다.
