# 018 - 봇 차단 사이트(Medium) 글 제출 허용

## 왜 (배경)

운영 중 에러 신고.

```
ClientException("'글 제목'을 찾을 수 없습니다. 모달 하단에 직접 입력해주세요.")
submit_view -> service.get_title
```

제출한 url 은 `https://bit.ly/4bHojO6` (실제 목적지는 Medium 글).

## 어떤 문제

실측으로 원인을 세 갈래로 확인했다.

| 확인 | 결과 |
| --- | --- |
| httpx 는 리다이렉트를 기본으로 안 따라감 | bit.ly → 301 본문 114바이트, `<title>` 없음 |
| Medium 은 Cloudflare 봇 차단 | 403 + `cf-mitigated: challenge` + "Just a moment..." |
| 차단이 간헐적 | 10회 중 2회 200, 8회 403 |

그리고 코드에 **우회로가 막혀 있는 버그**가 있었다.

```python
if response.status_code >= 400:   # Medium 은 403 이라 여기서 중단
    raise ClientException(...)
# 제목을 직접 입력한 경우에는 status_code만 확인 후에 return   ← 도달 불가
```

모달은 "하단에 '글 제목'을 직접 입력해주세요"라고 안내하는데, 정작 403 이 나는
Medium 글은 **제목을 직접 입력해도 제출 자체가 불가능**했다. 주석의 의도와 실제
흐름이 어긋나 있었다.

## 어떻게 해결

봇 차단과 진짜 403 을 구분해서, 봇 차단일 때만 url 을 통과시킨다.

- `_is_bot_protected()` 추가: `403 AND cf-mitigated 헤더 존재`
  Cloudflare 는 챌린지에만 이 헤더를 붙인다. 권한 거부 403 에는 없어서 안전하게 갈린다.
  (실측: Medium 403 → `cf-mitigated=challenge` / httpbin 403 → 헤더 없음)
- 봇 차단이면 제목 직접 입력값을 받아 통과. 미입력이면 직접 입력하라고 안내.
- 404 와 일반 403 은 기존대로 차단 (검증 정책 유지).
- 직접 입력값 읽는 위치를 상태 코드 검사 앞으로 옮겨 우회로를 되살렸다.

## 결과 / 범위 밖으로 남긴 것

Medium 글을 제목만 직접 입력하면 제출할 수 있다.

다만 **자동 제목 인식은 여전히 안 된다.** 조사 중 두 가지를 더 찾았는데 이번 범위에서는
제외했다 (사용자 결정 2026-08-13, "간단하게").

- `follow_redirects=True` 미적용 → bit.ly 등 단축링크는 계속 수동 입력 필요
- Medium 은 SPA 라 `<title>` 이 그냥 `"Medium"`. 진짜 제목은 `og:title` 에 있다.
  (실측: `og:title = '아내가 바이브 코딩을 시작했다 (3편)'`)
  → 이 둘은 세트로 넣어야 의미가 있다. 지금 리다이렉트만 켜면 제목이 "Medium" 으로
  저장돼 오히려 나빠진다. 자동 인식이 필요해지면 그때 함께 적용할 것.

## 사용자 검증 방법

1. **정상** 슬랙에서 `/제출` → 일반 블로그(velog 등) 링크만 넣고 제출 → 제목이 자동으로 들어감.
2. **이번 수정 지점** Medium 링크를 넣고 제목을 비워둔 채 제출 → "이 사이트는 자동 확인을
   차단하고 있어요. 모달 하단에 '글 제목'을 직접 입력해주세요." 안내.
   같은 링크에 **제목을 직접 입력**해서 제출 → **정상 제출됨** (기존에는 여기서 막혔다).
3. **엣지** 없는 주소(404)를 넣고 제목을 입력해도 → 기존대로 차단되는지 확인.
4. Medium 차단은 간헐적이라, 2번에서 안내가 안 뜨면 200 으로 통과한 경우다. 이때는 제목이
   "Medium" 으로 들어가는데 이는 위에 적은 범위 밖 항목이다.
